# 懂王 AI 应用开发训练营课程资料（项目演示版）

> 说明：本文档是“懂小智”语音课程顾问项目的演示知识数据，用于验证 RAG 检索、回答约束和转人工流程。价格、开班日期、优惠政策等动态信息不在本文档中，必须由人工老师确认。

## 课程定位

本课程面向希望把大模型能力做成可运行项目的学习者。重点不是只会调用一次模型接口，而是完成一个可展示、可解释、可部署的 AI 应用项目。

课程采用项目驱动方式，主线项目是“懂小智——实时语音 AI 课程顾问”。项目链路包括：浏览器采集语音、RTC 实时传输、ASR 语音识别、知识库 RAG 检索、大模型生成回答、TTS 语音合成，以及服务端监控和异常排查。

## 适合人群

- 会使用电脑和命令行，希望进入 AI 应用开发方向的初学者。
- 有 Python 基础，但缺少完整项目经验的开发者。
- 从测试、运营、产品或传统开发岗位转向 AI 应用开发的人。
- 想为简历增加一个能现场演示、能说明技术取舍的项目的人。

## 学习前置要求

- 能完成基础文件操作，并愿意学习终端命令。
- 了解 Python 变量、函数和字典即可；不会的内容可在项目中补齐。
- 无需预先掌握语音算法、向量数据库或大模型训练。
- 学习过程中需要自行注册云服务账号，并保管好 API Key、Access Key 和 Secret Key。

## 六阶段学习路线

### 第一阶段：开发环境与项目基线

目标：在本地启动前端和 FastAPI 服务，理解前端、后端、云服务各自负责什么。

学习内容：Git 分支、Python 虚拟环境、依赖安装、环境变量、`.env` 密钥隔离、Swagger 接口文档和健康检查。

阶段成果：本地服务可以访问，配置项能够通过健康检查验证，真实密钥不会提交到 Git。

### 第二阶段：实时语音链路

目标：跑通用户说话到 AI 语音回复的完整链路。

学习内容：RTC 房间、用户与智能体、麦克风权限、ASR、TTS、音频上下行，以及实时场景中的延迟取舍。

阶段成果：浏览器能够加入房间，语音可以被识别，模型回复可以被合成为语音播放。

### 第三阶段：大模型服务接入

目标：让本地 FastAPI 服务安全调用火山方舟在线推理端点。

学习内容：API Key 鉴权、Endpoint ID、流式输出、系统提示词、历史消息和 Token 使用量。

阶段成果：通过 Swagger 调用 `/debug/chat`，能够收到模型的流式文本回复。

### 第四阶段：课程知识库与 RAG

目标：让模型先检索课程资料，再依据资料回答，降低编造课程信息的风险。

学习内容：文档清洗、切片、向量化、语义检索、Top-K、检索增强生成和无结果降级。

阶段成果：用户询问课程内容或学习路线时，`/debug/rag` 能返回相关片段，`/debug/chat` 能生成有资料依据的回答。

### 第五阶段：RTC 接入自定义 LLM 服务

目标：把本地 RAG 对话能力接入实时语音智能体。

学习内容：HTTPS 公网回调、请求与响应协议、流式回调、超时、错误日志和临时公网隧道。

阶段成果：用户在 RTC 房间说话后，智能体通过自建 FastAPI 服务完成“检索—生成—语音回复”。

### 第六阶段：测试、文档与简历交付

目标：把“能运行”整理成“能展示、能讲清楚”。

学习内容：测试用例、边界场景、架构图、部署说明、问题复盘、演示脚本和简历项目描述。

阶段成果：形成可复现的 README、测试记录、项目截图、演示视频素材和简历表述。

## 项目能学到什么

- 使用 FastAPI 设计调试接口和业务回调接口。
- 使用环境变量隔离云端密钥，避免凭证进入代码仓库。
- 调用火山方舟大模型，并处理流式响应和对话历史。
- 建立知识库，理解文档切片、召回和 RAG 的工作过程。
- 串联 RTC、ASR、LLM、RAG、TTS，理解实时语音 AI 的系统架构。
- 使用日志和逐段验证定位麦克风、语音识别、模型和语音合成故障。
- 把技术实现整理为可展示的作品集和可复述的面试材料。

## 学习方式

- 每个阶段先解释目标和原理，再完成一个可验证的小结果。
- 遇到问题按链路逐层排查，不同时修改多个环节。
- 学员需要亲自完成涉及账号授权、付费确认、密钥查看和浏览器权限的操作。
- 代码编写、配置模板、接口测试、文档整理可以在指导下完成。

## 常见问题

### 零基础能不能学？

可以，但需要愿意动手。课程会从环境、接口和配置开始，一步一步完成项目；遇到 Python 或网络基础概念时，需要同步补课和练习。

### 学完能得到什么项目？

可以得到一个实时语音 AI 课程顾问项目。它包含前端语音交互、FastAPI 后端、火山引擎实时音视频与语音服务、方舟大模型、知识库 RAG，以及测试和项目文档。

### 为什么要使用 RAG？

课程、政策和业务资料会变化。RAG 先从指定知识库检索相关片段，再把片段交给大模型生成答案，可以减少模型凭空编造内容，并让资料更新不依赖重新训练模型。

### RAG 和模型微调有什么区别？

RAG 主要解决“让模型查询外部资料”的问题，资料可以随时更新；微调主要改变模型的行为模式或特定能力，需要准备训练数据并执行训练。这个项目优先使用 RAG，因为课程资料需要方便维护和追踪。

### 为什么实时语音场景关闭深度思考？

实时对话对响应延迟敏感。深度思考会增加模型生成前的等待时间，容易让用户误以为系统没有响应。课程咨询以直接、可核验的回答为主，因此默认关闭深度思考；复杂的非实时分析可以另外开启。

### 可以保证就业或薪资吗？

不能。课程目标是帮助学习者获得项目实践、技术理解和表达材料，不承诺岗位、薪资或面试结果。
